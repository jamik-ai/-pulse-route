# Пульс маршрута — инструкция для жюри

Система прогнозирует опоздание автобуса на остановке **за 10–15 минут** по потоку телеметрии NDTP и показывает
диспетчеру, кто опоздает, где, почему и что можно сделать.

## 1. Открыть работающую систему

- **Дашборд:** https://2-26-85-218.sslip.io — вход: логин `admin`, пароль `admin` (стенд с синтетикой — https://synth.2-26-85-218.sslip.io, тот же вход).
- При первом входе запускается короткое обучение. Повторить его можно в «Настройки → Как пользоваться».
- **Swagger backend:** https://2-26-85-218.sslip.io/docs — открыт без входа; для пробных запросов к закрытым методам нажмите «Authorize» и введите admin / admin
- **Документация кода (Sphinx):** https://2-26-85-218.sslip.io/code-docs/ — открыта без входа

## 2. Подать поток телеметрии

**Вариант А — исторический датасет (запускается сам).** Архив validate за 06.01.2026 проигрывается с 06:00
**как настоящий NDTP-поток по TCP**: по одному соединению на терминал, с handshake и CRC. Скорость — в «Настройках»
(×1 — реальное время, ускорение — для показа; кнопка внизу панели «Архив 06.01 · ×1» открывает их). Пока идёт
архив, это видно по фиолетовой пометке «Архив» — это не текущая обстановка в городе.

**Вариант А2 — синтетика «несколько машин на маршруте».** Отдельный стенд https://synth.2-26-85-218.sslip.io (тот же логин) или «Настройки → Данные → Синтетика» на основном: 39 ТС, по 3 на каждом из
13 реальных маршрутов с интервалом 12 мин. Телеметрия построена по реальным дорогам и расписанию, распределение
отклонений подогнано под реальное (медиана ~30 с, 90-й перцентиль ~260 с, 26% опозданий > 2 мин). На лентах видны
несколько автобусов одного маршрута и их сбивание в пары. Вернуть архив — там же.

**Вариант Б — эмулятор NDTP организаторов.** При локальном запуске (см. п. 5):
```bash
./scripts/emulator_start.sh 11 1000   # 11 терминалов → наш NDTP-сервер :9201
./scripts/emulator_start.sh stop
```
Эмулятор шлёт случайные координаты около Москвы с текущей датой. На нём видны приём и разбор пакетов
(«Состояние системы»: пакеты/с, 0 ошибок CRC). Прогнозы строятся по расписанию 06.01, поэтому для них нужен
вариант А.

**Вариант В — API:** `POST /api/replay/start {"speed": 5, "start": "2026-01-06 07:00"}` (Swagger).

## 3. Где смотреть прогнозы и алерты

| Что | Где |
|---|---|
| Сколько событий в ближайшие 10–15 мин | Сводка вверху левой панели; счётчики «новые / в работе / нет данных» |
| Ленты маршрутов (вкладка «Ленты») | Рейс каждого ТС: остановки, где ТС сейчас и где должно быть по графику, отставание, «нет GPS» |
| Очередь событий | Слева во вкладке «Ленты»: «Новые / В работе / Завершено». ТС, опоздание или **раньше плана**, остановка, «план → прогноз». «Принять в работу» (Enter), «Отложить» (S), ↑↓ |
| Карточка события в лентах | Нитка графика (план / факт / прогноз), мини-карта, вероятность, интервал ~80%, свежесть GPS и прогноза, вероятная причина, журнал |
| Карта сети | Линия текущего рейса каждого ТС по расписанию, проложенная по дорогам. Метки ТС окрашены по риску: зелёный / жёлтый / красный, стрелка показывает курс. Новые рейсы достраиваются автоматически (`POST /api/routes/rebuild`) |
| Карточка инцидента | Клик по ТС. Прогноз и P(опоздание > 2 мин), интервал ~80%, участок «остановка → остановка», **время выдачи предупреждения и запас (11–15 мин)**, текущее отклонение, скорость на сегменте, время простоя, причины (SHAP), сценарии |
| Без связи / нестабильный GPS | Фильтр «Без связи», пометка «GPS нестабилен» |
| Отчёт диспетчера | «Аналитика» → «Скачать CSV» или «Открыть для печати / PDF»: события, доля взятых в работу, время реакции, журнал |
| BI-аналитика | Вкладка «Аналитика»: алерты во времени, онлайн-ошибка по фактам проезда, распределение, производительность, таблица ТС |
| Метрики системы | Клик по статусу «Демо/В эфире»: пакеты/с, ошибки CRC, задержка ML p50/p95, пересчёт такта |

## 4. Проверить надёжность самостоятельно

```bash
docker stop delay-ml      # дашборд: «ML-модуль недоступен», прогнозы продолжаются по правилу
docker start delay-ml     # через ~5 с backend сам возвращается на модель
curl -X POST .../api/replay/stop   # «Нет связи», последнее состояние остаётся на карте
```
Наши замеры — в `docs/RELIABILITY.md`.

## 5. Запуск с нуля (Docker)

```bash
git clone https://github.com/jamik-ai/-pulse-route.git pulse-route && cd pulse-route
unzip /путь/к/dataset.zip -d data          # датасет хакатона (или DATASET_DIR в .env)
cp .env.example .env                       # логин/пароль дашборда
docker compose up -d --build               # ml + backend; архив сразу проигрывается как поток NDTP
# http://localhost:8080 (дашборд), :8080/docs (Swagger backend), :8001/docs (Swagger ML)
```

## 6. Воспроизвести скор Data Science в потоковом режиме

```bash
./run.sh python -m src.realtime.stream_submission
# NDTP-кадры → разбор/CRC → OnlineEngine (признаки строго ≤ T) → ML → output/submission_stream_validate.csv
```
Результат совпадает с загруженным `submission.csv` (98.7% точек до 0,1 с, максимум 1,3 с).
Про академическую честность — раздел в README: факты расписания и синтетические ТС в модели не используются.
