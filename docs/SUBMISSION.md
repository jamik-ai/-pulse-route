## Кратко о решении
«Пульс маршрута» (команда venik) — система раннего предупреждения об опозданиях наземного транспорта. Она принимает поток
телеметрии NDTP, в реальном времени накладывает его на плановое расписание и прогнозирует опоздание на остановке,
**плановое прибытие на которую ожидается через 10–15 минут**, с вероятностью, интервалом и причиной. Фактическое
прибытие может отличаться от планового окна. Результат выводится на дашборд диспетчера.

Три логических компонента в двух Docker-сервисах (`ml` и `backend`):
- **ML-сервис** (FastAPI + CatBoost): инференс, P(опоздание), интервал, причины, перезагрузка модели;
- **Backend** (FastAPI): NDTP-сервер, онлайн-движок, API, оркестрация, деградация;
- **BI-дашборд**: ленты маршрутов, очередь событий, карта OSM или Яндекс, карточка события, аналитика и отчёт; статические файлы обслуживает Backend.

## Точность
- Лидерборд Data Science: **0.752**. Честная модель без утечек, результат воспроизводится из потока NDTP.
- Ошибка на test: **64,4 с** против 93,4 с у baseline. CV на всех реальных точках: 62,4 с (строгая) / 60,7 с (как validate).
- Онлайн на потоке, все 13 ТС за день (`python -m src.realtime.check_all`: NDTP → онлайн-движок → сверка с фактами
  `labels_test`, 349 точек): MAE **57 с** против 93 с у подсказки `cur_dev_s` и 104 с у «нуля»; плановый горизонт 11–15 мин
  во всех прогнозах. Опоздания > 2 мин: предупреждение выдано по 70 из 86 (81%), ложных — 20 из 90 предупреждений.
  Ранние прибытия < −1 мин: помечены 36 из 49. Слабое место — ТС 122048 (кольцевой рейс, проезды остановок по GPS
  детектируются плохо): 3 из 7 опозданий.
- Калибровка на тех же 349 точках (один день, `labels_test`): интервал ~80% накрыл факт в 91% случаев (на событиях
  с карточки — 79%), P(опоздание > 2 мин): AUC 0,97, Brier 0,071; в диапазоне P 0,3–0,7 вероятность занижена (опоздало ~82%).
  Эти точки были в обучении, независимая CV-оценка скромнее: AUC 0,86, Brier 0,114 — подробно в docs/RELIABILITY.md.

## Производительность (подробно — docs/RELIABILITY.md)
- **Латентность ML на батч всех ТС:** p50 ≈ 100–120 мс, p95 ≈ 180–300 мс (замер 27.09 на ×20: 97 / 298 мс).
  Пересчёт такта (признаки + ML) ≈ 0,3–0,4 с.
- **Поток:** 50–95 пакетов NDTP/с на 2 vCPU, 0 ошибок CRC, 0 опоздавших точек на 106 тыс. пакетов.
- **Холодный старт:** ML 10,7 с, backend 13,8 с.
- **Деградация:**
  - ML недоступен → прогноз по правилу, баннер, автовосстановление;
  - обрыв NDTP → «Нет связи», последнее состояние, переподключение;
  - GPS-выбросы фильтруются для отображения.

## Реализованные дополнительные возможности
1. **Маршрутная сеть и Map Matching.**
   - **Нитка маршрута берётся из планового расписания:** рейс → последовательность остановок → путь по дорогам
     (свой OSRM на выгрузке OSM Москвы, с учётом направления движения). У каждого ТС на карте линия того рейса, который оно выполняет сейчас.
   - **Новые варианты рейсов backend находит и достраивает сам** — в фоне, при старте и по
     `POST /api/routes/rebuild`. До готовности показывается линия по остановкам. Дашборд подхватывает обновление без
     перезагрузки. Готовые пути кэшируются: в работе внешний сервис не нужен, а для продакшена достаточно своего
     контейнера OSRM с выгрузкой OSM Москвы.
   - **Живая телеметрия накладывается на нитку графика:** детекция проездов остановок по GPS (медиана ошибки 5 с),
     проекция позиции на отрезок между остановками, фильтр телепортаций.
2. **Рекомендации и what-if:** в карточке события — до трёх мер под причину сбоя (связаться с водителем, приоритет
   на светофорах, резерв или укороченный рейс, придержать при раннем прибытии). Где возможно, у меры — оценка модели
   «+4,1 → +2,3 мин» (пересчёт прогноза при изменённых скорости и простое); честно помечено как модельная оценка.
3. **Ансамбль моделей:** 2 × 5 CatBoost (поправка к отклонению + прямая задержка), классификатор P(late),
   квантильная модель с конформной калибровкой интервала (покрытие 78–81% при целевых 80%).
4. **Объяснимость:** SHAP-вклады, сгруппированные в понятные причины: «длительный простой», «проблемный участок
   по прошлым кругам», «накопленное отклонение».
5. **Онлайн-оценка точности** по фактическому проезду остановок и **обратная связь «Не так»** в датасет дообучения.
6. **Дообучение без простоя:** `train.py --final` → `POST /v1/model/reload`.
7. **Рабочий экран диспетчера:** «Ленты маршрутов» (положение ТС и график на одной ленте, «нет GPS»), очередь
   событий «Новые → В работе → Завершено» с ранними прибытиями отдельным типом, свежестью данных и журналом,
   мини-карта и нитка графика в карточке.
8. **Отчёт о работе диспетчеров** (CSV / PDF): события, доля взятых в работу, время реакции, журнал действий.
9. Вход с сессией, HTTPS, настройки аккаунта, значок статуса сети, обучение, горячие клавиши.
