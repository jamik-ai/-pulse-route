Обзор
=====

Задача
------

Диспетчер наземного транспорта обычно узнаёт об опоздании постфактум. «Пульс маршрута» переводит работу в
проактивный режим: каждые 5 минут времени потока для каждого ТС строится прогноз задержки на **первой остановке,
плановое прибытие на которую попадает в окно (T+10 мин, T+15 мин]**. Если опоздание вероятно, диспетчер видит
событие заранее — с временем «план → прогноз», вероятностью, интервалом, причиной и рекомендацией.

Как это работает
----------------

1. **Поток.** Бортовые терминалы (или эмулятор организаторов, или проигрывание архива) шлют кадры NDTP по TCP.
   Backend разбирает их (CRC-16, ``NPH_RESULT``), отбрасывает недостоверные координаты и дубли.
2. **Наложение на график.** Для каждого ТС хранится буфер телеметрии и плановое расписание: по GPS
   детектируются проезды остановок, считаются текущее отклонение, скорость на сегменте, время простоя.
3. **Прогноз.** На каждой границе 5 минут (момент T) признаки строятся строго по данным ≤ T и батчем уходят в
   ML-сервис: задержка, P(опоздание > 2 мин), интервал ~80 %, причины (SHAP).
4. **Диспетчер.** Дашборд показывает карту с цветом риска, ленты маршрутов, очередь событий и карточку с
   рекомендациями; действия диспетчера пишутся в журнал и отчёт.

     - ML p50 ≈ 100 мс, p95 ≈ 300 мс на батч всех ТС; пересчёт такта 0,3–0,4 с

Академическая честность
-----------------------

Модель не использует известные утечки датасета: факты расписания будущих остановок, синтетические ТС
``9000xxx`` (копии test/validate) и признак времени суток. Это проверяют тесты ``tests/test_no_leak.py``,
а совпадение потокового и офлайн-прогноза — ``tests/test_features_parity.py``.
