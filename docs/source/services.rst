Сервисы и API
=============

ML-сервис
---------

.. list-table::
   :header-rows: 1

   * - Метод
     - Назначение
   * - ``POST /v1/predict``
     - Батч признаков → задержка, P(опоздания), интервал, причины
   * - ``GET /v1/model``
     - Версия модели, состав ансамбля, латентность
   * - ``POST /v1/model/reload``
     - Перечитать модели после дообучения — без перезапуска
   * - ``GET /health``
     - Готовность

.. automodule:: src.ml_service.app

Backend
-------

Основные эндпоинты (полный список — Swagger ``/docs``):

.. list-table::
   :header-rows: 1

   * - Метод
     - Назначение
   * - ``GET /api/state``
     - Снимок для дашборда: поток, KPI, ТС с прогнозами и событиями
   * - ``GET /api/ribbons``, ``GET /api/vehicles/{id}/thread``
     - Ленты маршрутов и «нитка графика» ТС
   * - ``POST /api/vehicles/{id}/whatif``
     - Пересчёт прогноза моделью при изменённых условиях (для рекомендаций)
   * - ``GET /api/analytics``, ``GET /api/report/dispatcher``
     - BI-аналитика и отчёт о работе диспетчеров (CSV / страница для печати)
   * - ``POST /api/actions``
     - Действия диспетчера: принятие в работу, «прогноз неверен», слежение
   * - ``GET /api/datasets``, ``POST /api/dataset``
     - Выбор данных: архив хакатона или синтетика
   * - ``POST /api/replay/start``, ``/speed``, ``/stop``
     - Управление проигрыванием архива

Клиент ML-сервиса
-----------------

При недоступности ML-сервиса backend не падает: прогноз по правилу (последнее известное отклонение), баннер на
дашборде, автоматический возврат к модели.

.. automodule:: src.backend.ml_client

Маршруты по дорогам
-------------------

Нитка каждого рейса строится по дорогам через остановки: перегоны кэшируются, строятся параллельно, с учётом
направления движения; где роутер даёт крюк, берётся реальный GPS-трек или плановая связь между остановками.
